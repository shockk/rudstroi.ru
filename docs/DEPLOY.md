# Деплой на Timeweb Cloud App Platform

Сайт — Next.js с сервером (SSR). На Timeweb он работает как **backend-приложение** и собирается автоматически при каждом push в `main`.

## 1. Создать приложение (один раз)

1. Панель Timeweb Cloud → **App Platform** → **Создать**.
2. Подключить GitHub и выбрать репозиторий `rudstroi.ru`, ветку `main`.
3. Фреймворк: **Next.js**. **Включить SSR** (иначе форма заявок не будет работать). Режим SSR нельзя переключить после создания — только пересоздать приложение.
4. Версия Node: **22**.
5. Команды (обычно определяются сами):
   - сборка: `npm ci && npm run build`
   - запуск: `npm start`
6. Конфигурация сервера: самая маленькая из предложенных. Записать цену в `docs/PROJECT.md` (вопрос №8).
7. Переменные окружения:
   - `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather;
   - `TELEGRAM_CHAT_ID` — ID чата или группы для заявок.
8. Включить **автодеплой** при push в `main`.

После сборки сайт откроется на техническом домене Timeweb с SSL.

## 2. Проверить

- Главная, страницы `/uslugi/.../` и `/privacy/` открываются.
- Отправить тестовую заявку — сообщение пришло в Telegram.
- Если заявка не дошла: логи приложения в панели, ищем строки `[lead]`.

## 3. Домен

1. В приложении → **Домены** → добавить `rudstroi.ru` и `www.rudstroi.ru`.
2. У регистратора создать записи, которые покажет панель (A-запись на IP приложения). Если домен в Timeweb — записи создаются автоматически.
3. Выпустить бесплатный SSL Let's Encrypt (продлевается сам).
4. Основной адрес — `rudstroi.ru`, `www` → редирект на него.

## Локальная разработка

```bash
npm install
cp .env.example .env.local   # заполнить токен и ID чата, если нужно проверить Telegram
npm run dev
```

Без токена в режиме разработки заявка просто печатается в консоль сервера.
